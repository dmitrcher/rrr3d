# MotorRock: сравнение Windows / macOS

В Windows 11 ARM64 под Parallels собраны оригинальные `Release|Win32` и
`Debug|Win32` (VC++ 2008 SP1, Direct3D 9, PhysX 2.8.4). На Mac используется
нативная ARM64 Debug-сборка с Metal/bgfx и Jolt. Обычная Windows Release
установлена отдельно: `C:\MotorRock\game-release\MR.exe`; диагностическая —
`C:\MotorRock\game-debug\MR.exe`.

Mac Debug также установлен в `~/Applications/MotorRock-Debug.app`.
В тестовой VM журнал запускается через `C:\MotorRock\game-debug\Launch-Debug.ps1`.

Это инструменты для измерения расхождений. Полное совпадение меню, всех эффектов
и физики всех 90 трасс ещё не подтверждено. Известные различия исходного порта
записаны в `MACOS_PORT_SOURCE_PARITY_FINDINGS.md`.

## Запуск и мост Parallels

Из корня репозитория на Mac:

```sh
# Mac: тот же игровой сценарий, который выбирает Windows _DEBUG.
RRR3D_SEED=42 RRR3D_AI_DRIVER=1 tools/parity/launch-mac.sh

# Windows: запуск в пользовательском сеансе виртуальной машины.
python3 tools/parity/parallels.py launch --seed 42 --ai-driver \
  --guest-output 'C:\MotorRock\logs\parity\windows-42'

# Управление Windows через существующий игровой помощник.
tools/windows_reference/motorrock-reference.sh build
tools/windows_reference/motorrock-reference.sh focus
tools/windows_reference/motorrock-reference.sh key f7
tools/windows_reference/motorrock-reference.sh key f8

# Копирование журналов и PNG из гостевой системы на Mac.
python3 tools/parity/parallels.py collect \
  --guest-output 'C:\MotorRock\logs\parity\windows-42' --out captures
```

Требуются установленный `prlctl`, работающая VM `Windows 11` (имя меняется
через `--vm`) и общий каталог Parallels `\\Mac\Home`. Для клавиш и визуальной
проверки Mac и пользовательский сеанс Windows должны быть разблокированы.
Мост не открывает сетевой сервер: он использует консоль Parallels и общий каталог.
Не запускайте вторую копию игры, пока первая работает.

В Windows можно запустить `tools/parity/launch-windows.ps1` непосредственно
в PowerShell. В Mac `RRR3D_MAC_APP` меняет путь к `.app`, `RRR3D_RUN_DIR` —
каталог результатов. Каждый запуск создаёт отдельный каталог. Значение seed
выводится в журнал; без `RRR3D_SEED` обе игры используют текущее время.

## Режимы и клавиши

- Mac Debug включает диагностический HUD по умолчанию. `--game-debug` включает
  его также в Release, сохраняя обычную кампанию и эффекты.
- Для сравнения с Windows Debug используйте Mac `--legacy-windows-debug`.
  Оригинальный `_DEBUG` пропускает заставки и часть видео, принудительно выбирает
  облачную погоду, запускает гонку без отсчёта и отключает некоторые контактные
  и колёсные эффекты. Поэтому Windows Debug нельзя считать эталоном всех
  эффектов обычной Release. Для их сравнения нужны обе обычные версии.
- `F7` передаёт машину игрока существующему ИИ; повторное нажатие возвращает
  управление. `RRR3D_AI_DRIVER=1` включает это при создании гонки.
- `F8` сохраняет текущий игровой кадр, в том числе меню: Windows PNG, Mac TGA.
  Каталог задаёт `RRR3D_CAPTURE_DIR`; без него Windows использует `Screenshots`
  рядом с игрой, Mac — `Screenshots` в каталоге сохранений приложения.
- `F1` сбрасывает автомобили, `F2` переключает HDR/Bloom, `F3` полноэкранный
  режим, `F6` отображает трассу ИИ. В Mac `F10` переключает HUD.

## Журнал загрузки и телеметрия

`RRR3D_TRACE_FILE` задаёт файл JSONL. Родительский каталог создают запускатели.
Mac Debug также пишет по умолчанию `~/Library/Logs/RRR3d/parity-trace.jsonl`.
Этот файл дополняется; для сравнения выбирайте отдельный файл на каждый запуск.
Windows требует запуска с переменной окружения, которую задаёт запускатель.

Каждая строка содержит UTC, монотонное время с миллисекундами, PID, платформу,
название события и конкретный ресурс/состояние:

- `rng.seed`, `session.begin`, `menu.state`, `race.begin`;
- `asset.begin` / `asset.ready` — имя ресурса при чтении; в оригинальной Windows
  `ready` означает открытие потока, а не завершение GPU-декодирования;
- `map.begin` / `map.ready` — загрузка карты в оригинальном движке;
- `video.request`, `video.begin`, `video.ready`, `video.complete` — этапы
  видеозаставки Windows; Mac записывает запрос/завершение и сообщения декодера;
- `log` — существующие сообщения о загрузке и ошибках;
- `ai.player`, Windows `ai.control` — передача управления и состояние ИИ;
- `physics.sample` — каждые 10 фиксированных шагов: номер шага, racer,
  позиция, quaternion, линейная скорость, скорость машины и прогресс трассы.
  На Mac дополнительно записываются газ/тормоз/руль, контакты, RPM и передача;
- события сохранения/запроса скриншота.

Физические состояния снимаются перед очередным фиксированным шагом, `tick`
указывает число уже пройденных шагов. Монотонное время разных ОС не имеет
общего начала; сравнивайте время относительно начала журнала, а физику — по
`tick` и `racer`. Частое логирование влияет на время загрузки и частоту кадров.

## Как сравнивать

Выберите одну карту, одну машину и цвет, одинаковую сложность, состав соперников,
профили без прогресса, seed, камеру и разрешение. Используйте одну передачу
управления ИИ с самого старта. Не нажимайте сброс или другие игровые команды
в одной версии без аналогичного действия в другой.

```sh
python3 tools/parity/compare.py captures/windows-42/trace.jsonl \
  captures/mac-42/trace.jsonl --out comparison

# Меню без физического журнала: пиксельная разница (нужен Pillow).
python3 tools/parity/compare-images.py windows-menu.png mac-menu.tga --out menu-diff

# Или кадры вместе с физическими журналами.
python3 tools/parity/compare.py captures/windows-42/trace.jsonl \
  captures/mac-42/trace.jsonl --out comparison \
  --images captures/windows-42/menu.png captures/mac-42/menu.tga
```

Результат: `report.json`, `physics.csv`, два CSV загрузочного таймлайна и,
если указаны кадры, `image-difference.png` / `image-report.json`. Несовпадающие
карты, seed, шаг времени или отсутствующие состояния помечаются как непригодная
пара; разные разрешения кадров отклоняются. Инструмент не назначает произвольный
порог «всё совпало». Позиционные ошибки требуют проверки параметров сценария;
пиксельная разница включает анимацию, шрифты и особенности разных рендереров.

## Первое сравнение меню

Сняты оригинальное Windows Debug и Mac Debug главные меню при 1920×1080.
Геометрия рамки/логотипа близка, но строки пунктов меню на Mac визуально выше
примерно на 25 пикселей. Также отличаются шрифт/его отрисовка и оттенки фона.
Средняя абсолютная пиксельная разница RGB: `[8.1458, 5.9520, 6.2875]` из 255.
В неё входят различающиеся курсор, выделенный пункт и Windows FPS HUD, поэтому
это первичная диагностическая разница, а не изолированная оценка рендера.
Исправление/калибровка расположения пунктов ещё не выполнено.

## ИИ и повторяемость: проверка 2026-10-10

Оригинальный ИИ содержит рандомизацию ветвления маршрута (`GetRandomNode`),
выбора оружия и момента постановки мин. Её воспроизводит порт. Обычная Windows
инициализировала `srand` текущим временем; теперь обе платформы принимают
`RRR3D_SEED` для контролируемого сценария. Одинаковый seed не уравнивает CRT
`rand()` Windows и Darwin, порядок вызовов случайных чисел или PhysX/Jolt.

Проведены пять автономных Mac-заездов по `Data/Map/World1/map1.r3dMap`, Marauder,
6 машин, 600 кадров с фиксированным шагом и ИИ машины игрока:

- seed 42 против повторного seed 42: **330 совпадающих образцов**, все записанные
  значения полностью одинаковы;
- seed 42 против seed 99: траектории отличаются; максимальная позиционная
  разница в этих образцах **25.2519 единицы мира**;
- дополнительные повторы с двумя скриншотами на итоговой сборке, оба seed 42:
  первый зафиксированный разрыв — `tick=159`, racer 4, далее максимальная
  позиционная разница **35.2475 единицы**. Совпадение первой пары не доказывает
  детерминизм игры. Общий RNG, порядок игровых событий и многопоточная физика
  требуют отдельной проверки; конкретная причина этого разрыва ещё не изолирована;
- ИИ игрока и всех пяти соперников двигался и продвигался по трассе;
- 34 теста Mac и 6 проверок анализатора прошли; отдельный video smoke подтвердил
  загрузку `Data/Video/Main_eng.avi`, показ/звук/seek и событие завершения.
- Windows Debug запущен: собственный игровой PNG подтверждает главное меню
  и отладочный HUD; сохранение F8 зарегистрировано как `screenshot.saved`.
  Затем запущена та же Intaria/map1 с Marauder: записаны 2232 физические образца,
  машина игрока под ИИ достигла скорости 42.152 единицы/с. F7 записал
  `enabled → disabled → enabled`, собственные PNG сняты также в гонке.

Первая пара воспроизвелась, но итоговые дополнительные повторы разошлись.
Следовательно, **фиксированный seed сам по себе не гарантирует одинаковую езду**
даже внутри Mac-версии, тем более между Windows и Mac. Для строгой последующей
калибровки нужен одинаковый поток случайных решений и воспроизведение ввода,
а затем сравнение контактов, подвески, оружия и эффектов по конкретным сценариям.

## Пересборка оригинальной Windows

Патч `tools/parity/windows-reference.patch` применяется к оригинальному SDK
`q4a/rrr3d` на коммите `eff933868c1fbdfd266738a403fac80084f2b51e`, где код лежит
в `prog/`. Он не содержит SDK PhysX/DirectX, Boost или Microsoft runtime.

```sh
tools/parity/apply-windows-patch.sh /path/to/windows-sdk-checkout
```

В Windows, после подготовки библиотек SDK и Boost 1.53 headers:

```bat
tools\parity\build-windows.cmd C:\MotorRock\source\prog Debug
```

Скопируйте `Debug\RRR3d.exe` как `MR.exe`, `Rock3dGame.dll`, `NetLib.dll` и PDB
в отдельную копию ресурсов, создайте пустой `Profile`. Debug использует
**обычный D3DX9 helper**, сохраняя `_DEBUG`, отладочную информацию и Debug CRT.
Для запуска нужен локальный VC90 Debug CRT из установленного Visual C++ 2008:
`VC\redist\Debug_NonRedist\x86\Microsoft.VC90.DebugCRT`. Он установлен в
тестовой VM рядом с игрой, но не распространяется через GitHub/архивы.
Предупреждения LNK4099 относятся к отсутствующим PDB сторонних Ogg/Vorbis,
а не к ошибке сборки игры.

## Редактор трасс

Редактор существует: `src/MapEditor` / оригинальный `prog/MapEditor`.
Это Windows MFC-приложение с Direct3D 9. Реальная попытка Windows Release
завершилась `fatal error C1083: afxwin.h: No such file or directory`:
установленный VC++ 2008 Express не содержит MFC. Для сборки требуется
совместимый полный Visual Studio/MFC toolchain и библиотеки исходного SDK.

Нативный интерфейс редактора под Mac не портирован. Запрос
`RRR3D_BUILD_MAP_EDITOR=ON` теперь явно сообщает об этом, вместо того чтобы
тихо пропускать редактор. Готовых сборок редактора для обеих платформ нет.
Дальнейшая работа — подготовка MFC-среды Windows и отдельный перенос интерфейса
редактора с сохранением формата карт.
