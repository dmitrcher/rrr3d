# MotorRock: контакт, трение и совместимость ориентации v51

Устранено расхождение `body-slide-x`: все 180 состояний совпадают с неизменённым Windows/PhysX 2.8.4 по словам float32, в двух самостоятельных повторах Mac-пробника. Текущая сохранённая матрица из 291 сценария проверяется отдельно от полной матрицы 608 сценариев. Цель устранения всех расхождений остаётся активной.

Исправления получены по первой расходящейся операции в оригинальном решателе, без подбора мощности, массы, сцепления или подвески:

- Windows рассчитывает нормальный и касательный импульсы из одной скорости точки и применяет их суммарный вектор один раз. Ограничение трения вычисляется через отношение, умножение и вычитание предыдущего импульса; прямой clamp даёт другую округлённую величину.
- Ось с нулевым коэффициентом трения также нужна: она компенсирует малую проекцию накопленного мирового вектора на неидеально ортогональные float-оси.
- Глобальный кватернион решателя вычисляется с произведением векторов перед скалярными слагаемыми. Старое вычисление seed и raw-material оставлено отдельно; касательные берутся из оригинальных столбцов кватерниона.
- При создании локальной точки кеша координата X суммируется в порядке XYZ. При восстановлении плеча контакта решатель суммирует XYZ для всех координат. Расхождения обнаружены на шагах 22 и 30 до применения сил.
- Ориентация актёра для игрового обработчика контакта воспроизводит публичный float-аксессор PhysX. Матрица Jolt расходилась по диагонали на шаге 30 и меняла изменённую нормаль.
- Накопленный вектор трения передаётся в отчёт о контакте. Прежний эксперимент применял трение, но выводил нулевой вектор. Точное соответствие оригинальному API contact-report пока не подтверждено: PhysX сообщает силы в своих преобразованных контактных координатах, а текущий Mac-отчёт использует реально приложенный мировой импульс.

Две прежние гипотезы о переносе material-frame между соседними контактами были отвергнуты по данным оригинального обработчика. Эти изменения полностью удалены из активного кода.

Длинный стенд выявил ошибку совместимости: оригинальное интегрирование сохраняет небольшую неединичность кватерниона, а вспомогательные операции Jolt требуют строго единичной ориентации. В 255864 сохранённых Windows-состояниях максимальная ошибка квадратной длины равна 1.9014973e-5. Отдельный строгий флаг допускает только ограничение 3e-5; исходный кватернион и формулы матрицы/вращения не изменяются. NaN и сильно неединичные данные по-прежнему отвергаются. В компактном внутреннем ключе кеша Jolt нормализуется только копия относительной ориентации. Неиспользуемые Jacobian-поля Jolt инициализируются единичными осями, тогда как Native-подготовка и применение силы получают исходные оси. Также убраны лишние старые вычисления позиции и момента, результат которых затем заменялся Native-аксессором.

Проверки:

- сохранённые Windows-референсы, два контроля и два кандидата для 291 сценария; сравнение float32 без допусков;
- 160 оригинальных private-contact строк на шагах 10, 11, 22 и 30, каждый набор в двух повторах: по 21 float32-полю, включая знак нуля;
- 1640 записей / 14264 слова float32: текущие C++-преобразования против Windows, компиляция O0 и O2;
- оригинальная и текущая версии Mat44/Quat проверены на трёх длинных/предельных Windows-ориентациях; слова матрицы и пяти вращательных операций сохранены, default-off и отклонение NaN/большой ошибки сохранены;
- полная Debug-сборка приложения и 53 CTest; отдельные длинные сценарии удара о стену и бордюр;
- полный стенд: 608 сценариев, 255864 состояния, два одинаковых повтора; 65 сценариев совпадают побитово, в 543 остаются расхождения. Полный отчёт хранит первые расходящиеся поля и шаги каждого сценария. Проверенные 291 сценарий включают дополнительные изолированные варианты и не являются подмножеством из 291 случая этой широкой матрицы.

Данные о положении, скорости, угловом моменте, кватернионе и восьми численных полях каждого колеса входят в контракт сравнения. Численные стенды не содержат компьютерных игроков. Пробник не читает ожидаемые состояния для расчёта физики, не подменяет геометрию записанными контактами и не корректирует состояние после шага.

Все шесть новых флагов по умолчанию выключены. Полный byte-exact before/after snapshot, patch, verifier и fresh replay находятся в [experimental/native-contact-friction-v51](../tools/calibration/experimental/native-contact-friction-v51/README.md). Это исследовательская сборка. Динамические пары, полный набор подвески/шин/торможения, API сил, игровая гонка, ИИ и графическое соответствие требуют своих проверок.
