# Боковая грань и вычисление углового момента v24

Цель полного физического совпадения с Windows остаётся активной. Работа остаётся
на контактах; следующие эффекты в изолированной лестнице не включены. ИИ отсутствует.
Оба новых флага принимают строго `1`, по умолчанию выключены. Установленные игры
сохраняют v14. Активный прототип — v23 с явным патчем `side-order-principal-v24.patch`;
SHA исходников до/после указаны в `side-order-principal-v24-base.json`.

## Отрицательная local-X грань

На наклоне около −90° нативный Windows callback начинает с другой вершины боковой
грани. Простое изменение направления обхода отклонено: оно дало 17 регрессий
каналов. Полный порядок задаёт одновременно начальную вершину и направление;
он включается `RRR3D_EXPERIMENT_NEGATIVE_X_FACE_ORDER=1` только для этой грани.

На 72 наклонных контактных сценариях (8 шагов, два повтора на каждой платформе)
максимальная ошибка скорости снизилась **0.0414664 → 0.000410243**, координат —
**0.00103132 → 0.0000181853**. Изменились три сценария; остальные 69 сохранили
показатели v23. Есть малая регрессия Y скорости в `frame-v23-p0-x0-y1`:
RMS 3.49393e−8 → 3.63160e−8. Все 72 ещё имеют строгий численный остаток.
Сопоставление почти совпадающих точек рёбер неоднозначно; исправление полного
порядка всех контактов этим не подтверждено.

В полной матрице изменились только `border-air-oblique` и `border-grounded`;
606 остальных сценариев имеют прежние comparator-показатели при этом флаге.
В `border-grounded` RMS скорости ухудшился 0.539436 → 0.539857, длины подвески —
0.0261495 → 0.0263493, также выросли отдельные X/Z компоненты. Поэтому изменение
порядка остаётся экспериментом и не продвигается в обычную игру.

## Угловой момент

Прежний snapshot вычисляет `L = inverse(I_world_inverse) * omega`. Обращение
полной float32 матрицы теряет точность при сильно различающихся главных моментах
инерции. Новый `RRR3D_EXPERIMENT_PRINCIPAL_MOMENTUM=1` восстанавливает инерцию
через её главные оси: `L = R * diag(1/invI) * transpose(R) * omega`.
Это исправляет вычисляемый snapshot и кинетическую энергию; solver не заменяется.

В `body-tilt-pitch` RMS ошибки L по Y снизился **105.422 → 20.5227**,
векторной ошибки L — **124.430 → 69.0483**; все X/Y/Z компоненты этого сценария
улучшились. Два прогона 180 шагов совпали точно.

В каждом полном профиле изменились показатели 461 сценария, включая два изменения
боковой грани. Сравнение с вариантом только боковой грани подтвердило полное
совпадение всех 608 физических потоков и фактических массовых свойств при
исключении поля angular_momentum. Координаты, скорость, ориентация и колёса
не изменились от нового вычисления L.

Общий RMS L в default снизился 87.8975 → 87.6903, однако в 255 сценариях RMS L
вырос. Например, `contact-free-box-depth5-speed0`: 0.0118786 → 0.171377.
В `body-tilt-roll` ошибка Lx выросла 5.34579 → 5.59129. Все регрессии по отдельным
каналам перечислены в `side-order-principal-v24-audit.json`; точность всего
углового поведения этим не подтверждена. Флаг также остаётся экспериментальным.

## Нативная диагностика углового момента

Новый Windows probe поддерживает `NX_ANGULAR_MOMENTUM_TRACE=1`: после solver
записывает omega, L, диагональную инерцию, world inertia/inverse inertia и
ориентацию массовых главных осей. Сняты два повтора шести сценариев / 624 отсчётов;
все sample и фактические массовые свойства точно совпали с исходным v14 эталоном.
Диагностические API-вызовы не изменили эти физические результаты.
Новый exe проверен certutil SHA-256: `8cdab3cb311453ecd18e344a4780bca40f5b4bb67f8b9628414855abd6816c3a`.

Девять значащих цифр восстановлены в float32 до арифметических сравнений.
Публичное `world inertia * omega` и варианты float/double продуктов имеют
остаток до 0.251326 в body-tilt-pitch. Текущая principal формула с double
промежуточными произведениями имеет остаток до 0.444693. Поэтому ни один
вариант не принят как точное воспроизведение SDK. Эти небольшие остатки
нужно отделять от значительно большей ошибки полного Mac прогона.
`experimental/analyze_native_momentum.py` воспроизводит численный аудит
по trace/repeat/baseline и сохраняет область достоверности.

## Проверки и дальнейшая работа

Оба профиля: 608 сценариев, 255864 отсчёта. Осталось 572 непройденных сценария.
С выключенными новыми флагами обе матрицы точно повторяют физические записи v23.
Лестница 00–02 снова совпала точно; 03 имеет прежние 12 контактных расхождений.
Прошли 53 CTest, дополнительно два inertia/frozen теста с включённым principal флагом.
Игровые physics smoke и трассы 0/16/48 прошли в обоих профилях; 64 остаётся непройденной.
Windows 11 VM проверена через `prlctl status`, состояние running. Caffeinate работает.

Следующие шаги: нативный angular-momentum trace, арифметика тензора и остаток solver,
clipping/rounding контактов, регрессия border-grounded. При изменениях повторять
пройденные этапы и всю матрицу по каждому каналу.

```sh
python tools/calibration/experimental/run_isolation.py --platform mac \
  --probe rrr3d_physics_spring_probe --reference-dir windows-isolation \
  --upper-face-winding --negative-x-face-order --principal-momentum \
  --out mac-v24-isolation
```

Runner сохраняет отчёты и останавливается на 03 с кодом 1. Это ожидаемый
непройденный контактный этап, не сертификат полного совпадения.
