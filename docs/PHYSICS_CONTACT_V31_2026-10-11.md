# Фактическая арифметика контакта Windows v31

В реальной Windows 11 VM Parallels прослежены подготовка и итерационный
решатель PhysX 2.8.4. Результат — точная реконструкция арифметики первых
контактов, **ещё не исправление Mac-физики**. Цель устранения всех расхождений
остаётся активной; 12 обычных изолированных контактов Mac ещё не пройдены.

## Область проверки

12 сценариев `isolate-03-contact-m{0,1,2}-h{0,1}-v{0,1}-f1`, каждый снят
дважды. Массы 300/1200/2400, два исходных положения и две скорости, 120 шагов
по 1/60 секунды, четыре biased итерации и один unbiased проход. Трение,
колёсные контакты, подвеска, двигатель и ИИ выключены. Изучается первый удар
корпуса о плоскую поверхность при единичной ориентации тела.

Windows SpringProbe и PhysX DLL сохранены от v30. Отдельный отладчик временно
ставит программные breakpoint и аппаратные watchpoint, читает действительные
строки решателя и состояния тел; численные входы решателя не подставляются.
В каждой серии все 120 физических состояний точно сохранены относительно
неизменённого v30 эталона. Семантические события и определённые численные поля
trace повторяются; timestamps, адреса heap, padding и неинициализированные поля
не входят в утверждение о повторяемости. Это не проверка влияния отладчика на
скорость исполнения.

| Проверка | Результат одного набора, подтверждённый вторым |
|---|---:|
| Расчёт Native effective mass из геометрии и инерции | 96/96 точно |
| Расчёт Native scaled bias из constraint error | 96/96 точно |
| Последовательное восстановление v, angular v и accumulated lambda | 480/480 входных состояний точно |
| Финальная линейная скорость первого удара | 12/12 точно |
| Существующая Mac effective mass при подставленной Native геометрии | 42/96 точно |

Predictor получает записанную контактную геометрию, ошибку ограничения и
начальное состояние Native тела. Он сам вычисляет effective mass и scaled bias,
затем проходит все 40 строк каждого сценария вперёд, без сброса состояния
к наблюдениям и без использования ожидаемых выходов. Наблюдаемые значения
служат проверкой. Геометрия и constraint error пока не генерируются независимо
на Mac; поэтому эти результаты нельзя засчитать как самостоятельный контакт.

## Найденные различия операций

Все операции ниже округляются до float32 отдельно. Для динамического тела
и статической поверхности, `R` — плечо от COM, `N` — нормаль после Native
преобразования quaternion, `I` — обратная инерция:

```text
C = cross(R, N)
D = I * C
K = 1 / (invMass + dot(N, cross(D, R)))
rawBias = constraintError * (1 / dt)
scaledBias = (rawBias * K) * 0.8
pointVelocity = v + cross(angularVelocity, R)
delta = K * -dot(N, pointVelocity) - scaledBias
total = oldLambda + delta
```

Векторная формула K математически эквивалентна Jacobian dot-product, но имеет
другой порядок округления. Она воспроизвела все 96 значений фактических
Native строк. В bias используется multiplication by inverse dt, а не деление
ошибки на dt. Unbiased проход обнуляет отрицательный bias.

При отсутствии clamp Native применяет исходный `delta`; его не восстанавливают
через `total - oldLambda`. Если clamp сработал, применяется разность ограниченного
total и старого lambda. Далее сначала вычисляется `force = N * delta`, затем
линейная поправка `force * invMass` и угловая `I * cross(R, force)`. Применение
delta к заранее вычисленному inverse-inertia response тоже меняет округление.

Формулы подтверждены указанными плоскими контактами. Контакт двух динамических
тел, ненулевая ориентация, тангенциальные строки и произвольные ограничения
ещё требуют собственных проверок; эти формулы нельзя автоматически переносить
во все Jolt joints.

## Доказанный исполняемый путь

Адреса — RVA проверенной x86 `PhysXCore.dll`, SHA-256:

```text
c03f0e20e99a6ca8d72c8627cf3b0108036a734123f75c652c2b78d3043dbdbb
```

Callback dispatcher `207440`, return from user callback `207775`, parent return
`20478d` ведут к backend lookup `8d8f0/7ea70`. Преобразование контактных данных
идёт через `74710`; окончательный 128-byte solver buffer наблюдается по `751ab`.
Инициализация численных строк: `841e0` → `84c74`. Фактически вызываемый
итерационный kernel: `1e7e50`. Hardware watch установлен на окончательный
buffer после подготовки; наблюдение более раннего массива было недостаточно,
поскольку массив перевыделяется. Это исключает прежнее ошибочное предположение,
что более ранние 136-byte converted contact records уже являются final solver rows.

Подробный layout и команды — в
[NativeSolverTrace](../tools/calibration/experimental/NativeSolverTrace/README.md).

## Следующее исправление и критерий принятия

Следующий эксперимент на Mac должен независимо реализовать порядок K, bias,
point velocity и применения импульса. Сначала требуется сверить отдельные
строки при контролируемой диагностической геометрии; затем обычные контакты
без подстановки Windows записей. Генерация контактных точек и constraint error
остаётся отдельной причиной расхождения, наклонные frame также ещё не закрыты.

После полного совпадения контакта повторяются ранее пройденные ступени
9 свободного движения +108 ускорения +48 гравитации, затем подключается
подвеска и последующие эффекты. В v31 эти 165 Mac сценариев не переснимались:
последнее подтверждение — v30. Mac SDK, адаптер и установленные игры в v31
не изменены. Последняя полная матрица — v27, 572 непройденных из 608 на профиль;
это исторический результат, а не свежий v31 прогон.
