# Арифметика контакта Mac v32

В настоящий ARM64 Mac-пробник перенесён порядок арифметических операций
контакта, измеренный внутри эталонной Windows/PhysX2.8.4. При отдельно
подставленной записанной геометрии и ошибке ограничения Native результат
совпадает:480/480 входных состояний строк решателя,96/96 effective mass,
96/96 scaled bias,12/12 положений и скоростей первого контактного шага.
**Самостоятельные контакты Mac пока не совпадают; цель остаётся активной.**

## Изоляция и переключатели

12 сценариев контакта кузова с плоскостью, массы300/1200/2400, два исходных
положения и две скорости. Каждый запускается120 шагов по1/60 секунды.
ИИ, оружие, двигатель, колёса, подвеска, трение и restitution выключены.
Рассматривается первый наблюдаемый контакт: шесть случаев speculative,
шесть penetrating. В низких исходных положениях первые ticks равны2/1,
а не3/2 из прежних impact-only контрактов.

Пять независимых строгих literal`1` флагов управляют effective mass, bias,
скоростью точки, сохранением исходного delta до clamp и вычислением force
перед применением обратной инерции. Проверены **все32 сочетания**:
32×12×2=768 фактических запусков. Полные состояния тел в повторениях совпадают,
семантические trace события также повторяются; timestamp/PID не сравниваются.

| Маска | Изменения | Точных Native входных состояний из480 |
|---:|---|---:|
| 1 | effective mass | 246 |
| 3 | + bias | 246 |
| 7 | + point velocity | 246 |
| 15 | + original delta | 246 |
| 31 | + force first | 480 |

Одна только force-first маска16 даёт249/480. Ни одно другое сочетание не
совпало во всех480 состояниях и всех12 первых положениях/скоростях. Маска0
использует прежний решатель и не выдаёт частные Native итерационные события.
Обычные полные120-шаговые состояния маски0 точно сохранены относительно v30.
Полный factorial содержит14880 наблюдаемых частных строк на повторение.

## Что изменено в исполняемом Mac-коде

В source block-PGS для dynamic/static normal contact при нулевых трении и
restitution добавлена отдельная экспериментальная ветка. Она использует
собственные состояния Mac и float32-операции без FMA; геометрия переводится
в Native Z-up с отдельным правилом знака для axial векторов. Решатель вычисляет
K через отклик скорости точки; bias через умножение на inverse dt; jv через
`v + cross(w,R)`; при отсутствии clamp применяет исходный delta, затем сначала
`force=N*delta`, после этого `force*invMass` и `I*cross(R,force)`.

Эти операции не получают ожидаемые Windows выходные скорости и не сбрасывают
Mac к наблюдаемым состояниям. Записанные позиции/separation и constraint error
подаются только явно обозначенными диагностическими режимами. Первый режим
`ordinary` ничего не подставляет, `points` подставляет геометрию одного шага,
`errors` дополнительно подставляет constraint error. Поле trace `scaled_bias`
при выключенном bit2 — кандидат Native bias, а не применённый legacy bias.

| Фактическая проверка | Результат |
|---|---:|
| Свободное движение, ordinary mask31, два повтора | 9/9 точно |
| Ускорение, ordinary mask31, два повтора | 108/108 точно |
| Гравитация, ordinary mask31, два повтора | 48/48 точно |
| Контактная ступень, ground off | 12/12 точно |
| Контактная ступень, ground on | 12/12 остаются |
| Только Native geometry, mask31, все120 шагов | 12/12 остаются |
| Native geometry + error одного шага, mask31, все120 шагов | 12/12 остаются |
| Свежая полная сборка Mac Debug | завершена; arm64 bundle проверен |
| Свежий CTest | 53/53 прошли |

Оставшиеся120-шаговые расхождения даже в `errors` ожидаемы: вмешательство
действует только в одном контактном шаге, далее Mac снова генерирует свои
контакты. Такой эксперимент локализует причину, но не заменяет исправления
геометрии. Переносимые capture helpers дополнительно повторили24 запуска
маски31 и точно воспроизвели семантику авторитетных записей.

## Ограничения и следующая ступень

Установленные игры и production SDK-патч этим экспериментом не обновлены.
Пять флагов по умолчанию выключены; canonical адаптер в Git не подменён
экспериментальным. Шестифайловый patch и before/after SHA contract позволяют
воспроизвести реально проверенные SDK/adapter изменения после v30.

Нужно независимо восстановить Native генерацию точек и constraint error,
добиться полного совпадения всех12 ordinary контактов, затем повторить165
ранних сценариев и подключать следующие эффекты по одному: подвеску,
амортизаторы, ограничители, трение и боковое скольжение. Наклонные frame,
динамические пары и restitution также требуют самостоятельных проверок.
Полная608-case матрица последний раз проверена в v27:572 непройденных на
профиль. Это исторический результат, не свежая проверка v32. Игровая геометрия,
ИИ и долгие заезды также не засчитаны как пройденные.
