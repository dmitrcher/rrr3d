# Самостоятельный расчёт ошибки контакта Mac v33

Mac теперь вычисляет ошибку ограничения самостоятельно. В первом контакте
всех12 изолированных сценариев **96/96 ошибок совпали с Windows даже без
подстановки геометрии**. При диагностически одинаковых точках контакта
совпадают также480/480 входных состояний решателя,96 effective mass/bias
и12/12 первых положений/скоростей. Подстановка Native ошибки из v32 больше
не нужна. **Все12 полных самостоятельных120-шаговых контактов ещё расходятся.**

## Найденная причина

В реальной Windows11 VM прослежены преобразования PhysX2.8.4 до пользовательского
callback. Converter сначала копирует исходную ошибку без изменения. Затем
обработчик материала преобразует вектор ошибки через quaternion исходного
контактного frame и обратно через frame материала, после чего вызывает setter.

Округление каждой операции отдельно до float32 имеет значение. SDK использует
quaternion rotation через `(w*w - 0.5)`, dot и cross, а не матрицу с предположением
об идеально единичном quaternion. Порядок dot различается в прямом и обратном
преобразовании. В исходном frame величины околоsqrt(0.5) уже округлены; поэтому
малое отклонение нормы quaternion меняет constraint error и накопленный импульс.

В примере m0h0v0 raw error`-0.05555553361773491` превращается в
`-0.055555522441864014`. Это получено из арифметики, без таблицы эталонных
значений или поправки, привязанной к конкретному сценарию. Для положительного
m0h1v0 normal error остаётся`0.04333381727337837`; при этом появляется малая
тангенциальная компонента, которую Native material flag0x20 обнуляет.

Новый ARM64 C++ helper генерирует raw/material quaternion из логической
геометрии fixture, без получения записанных quaternion. В отдельном арифметическом
стенде входной raw scalar остаётся записанным Native значением; все96 generated
quaternions, промежуточных векторов и normal setter values совпали в обоих повторах.
В действительном Mac-пробнике raw scalar берётся из его separation и skin.

## Проверки и область результата

12 случаев, массы300/1200/2400, два начальных положения и две скорости,
120 шагов по1/60 секунды. Шесть первых контактов speculative, шесть penetrating.
ИИ, оружие, двигатель, колёса, подвеска, трение и restitution выключены.
Все24 Native запуска сохранили все120 физических состояний относительно
неизменённого v30 baseline. Heap addresses, padding и undefined поля trace
не входят в проверку повторяемости; определённые численные поля входят.

| Режим фактического Mac-пробника, два повтора | Результат |
|---|---:|
| `points`: записанная геометрия, ошибка вычислена Mac | 480/480 состояний,12/12 первых положений/скоростей точно |
| `ordinary`: собственные геометрия и ошибка | 96/96 первых ошибок точно;12/12 полных контактов остаются |
| `errors`: дополнительная явная Native error replay | контроль v32 сохраняется,480/480 точно |
| `control`: новые флаги выключены | все120 состояния всех12 случаев сохранены относительно v32 |
| Свободное движение +ускорение +гравитация, новый флаг включён | 165/165 точно в обоих повторах |
| Ground-off контактная ступень | 12/12 точно |
| Свежая полная сборка Mac Debug | arm64 bundle подписан и проверен;1200 assets,14 movies |
| Свежий CTest | 53/53 прошли |

`ordinary` совпадает в первых положениях/скоростях лишь6/12 случаев —
speculative случаи ещё не получают контактного импульса. Это нельзя засчитать
как успешную проверку удара. Все полные120-шаговые контакты непройдены;
в `points` вмешательство действует только на один шаг, затем снова работают
собственные точки Mac.

Новый строгий literal`1` переключатель
`RRR3D_EXPERIMENT_NATIVE_CONTACT_ERROR_FRAME` выключен по умолчанию.
Derived error и diagnostic replay сохраняются в разных полях; trace показывает
`derived_error:true, diagnostic_error:false` при самостоятельном расчёте.
Ветка применяется в прежней экспериментальной области zero-friction/restitution
source block-PGS dynamic/static контактов. Наклонные seed/frame ещё не приняты.
SDK/adapter изменения опубликованы отдельным шестифайловым слоем после v32;
установленные игры и canonical production adapter не обновлены.

## Оставшееся расхождение

У m0h0v0 четыре угловые точки первого контакта совпадают. Четыре точки
пересечения рёбер с диагональю triangle mesh расходятся поX/Y:
Native использует величины около±0.799987793/±0.799957275, Mac —±0.800018311.
Первый normal error этих точек уже совпадает. Следующий шаг — восстановить
порядок арифметики генератора пересечений, без подстановки координат Windows,
затем пройти все12 ordinary контактов целиком. Только после этого подключать
подвеску, ограничители, трение и боковое скольжение.

Полная608-case матрица последний раз проверена в v27:572 непройденных на профиль.
Это историческое измерение, не свежая проверка v33. Долгие заезды, игровая
геометрия, динамические пары, restitution и ИИ также остаются в цели.
