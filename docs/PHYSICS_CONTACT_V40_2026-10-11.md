# v40: сохранение мировой системы координат контакта

Остаётся экспериментом с выключенным по умолчанию флагом
`RRR3D_EXPERIMENT_NATIVE_CACHE_FRAME=1`; требуется полный v39 набор.
Масса, двигатель, тормоза, пружины, демпфирование и коэффициенты шин не
подстраивались. В каждом фактическом профиле этого прогона все 8 scales = 1.
Эталонные Windows probe, PhysXCore и игра не заменялись.

## Причина и исправление

В p7-x1-y0 шаг 2 новая геометрия, глубины и сохранённые локальные позиции
уже совпадали. Но Mac вычислял transverse error через заново собранный
callback quaternion `actor * (inverse(actor) * rawWorld)`. Это другая
округлённая величина, чем мировая система исходной сырой точки контакта,
сохраняемая Native при создании cache. Их нельзя использовать взаимозаменяемо.

Mac ранее подавал q.y=-0.70710688829422, q.w=0.7071069478988647;
Native raw point сохранял -0.7071067690849304 и 0.7071067690849304.
У первой точки transverse.z было -1.7271304386667907e-9 против
Native 2.878550731111318e-10. Отсюда первая разница constraint error и bias.

Кандидат строит независимый rawWorld(normal) при создании cache и сохраняет
его при повторном использовании точки. Callback/material преобразование
остаётся отдельным расчётом. Никаких записанных Windows состояний или
названий сценариев реализация не читает. Добавлена отдельная read-only
трассировка входов cache, actor pose, локальных опор и transverse error.

## Проверки

- 189 изоляционных сценариев: точное совпадение, два повтора.
- 72 наклонённых контакта по 120 шагов: 18 точных, 54 с остатками;
  ранее 16 точных. Новые полные совпадения p7-x1-y0 и p9-x1-y0.
- Ни одно прежнее полное совпадение не потеряно. Disabled control точно
  воспроизводит v39 во всех 72 сценариях, каждый режим повторён дважды.
- Положение улучшилось в 7 сценариях, ухудшилось в 2; скорость улучшилась
  в 4, ухудшилась в 4. Все ухудшения сохранены в полном отчёте.
  В p9-x2-y0 ошибка положения выросла с 0 до 6.272360002726934e-6,
  скорости с 4.947726748136928e-7 до 8.610156792374744e-6.
  Сценарий и раньше не был полностью точным: первое расхождение остаётся
  на tick 2. Это не разрешение включать кандидата в production.
- Глобальные максимумы остаются: позиция 0.0022348796830243055,
  скорость 0.04756051606417113.
- Четыре подробных сценария: все 360 solver rows × 8 полей на шагах 0–2
  точны, два повтора. Полные 120-step состояния всех четырёх точны.
- Во всех 12 подробных case/step комбинациях raw frame и transverse
  компоненты совпадают с независимо записанным оригинальным PhysX.
  Локальные опоры точны. У p7 остаются прежние отличия normal0 в 8 точках:
  Mac x=-0.009999833069741726, Windows x=-0.009999834932386875.
  Они явно сохранены как незакрытая зацепка; нельзя назвать всё cache точным.
- Полная Debug app собрана и подписана: 1200 assets, 14 movies.
  Все 53 CTest прошли. Это не новая визуальная проверка гонки Mac.

Цель не достигнута. Дальше: локальные нормали при transport/cache creation,
остатки p9-x2-y0 и общая матрица подвески/шин/AI после исправления контактов.
Числа и portable verifiers: `tools/calibration/experimental/native-cache-frame-v40`.

## Дополнение к проверке двигателя

По PDB и машинному коду установлен адрес оригинального Debug CalcTorque.
Новый helper вызывает саму функцию из неизменённой Rock3dGame.dll, а не
копию формулы; конструктор motor description тоже оригинальный.
При явно выставленной в helper точности x87 PC53: 72 строки точно
повторяют прежний Windows helper; 27 отличаются от Mac collapsed expression.
При PC24: все 72 совпадают с Mac последовательной исходной формулой;
15 отличаются от collapsed expression. По два идентичных повтора каждого.

Поэтому ещё нельзя выбрать double либо float для production только по
standalone запуску. Проверка точности реального игрового потока после D3D
и GameCar → NxWheelShape остаётся обязательной. Попытки запуска полного
игрового tracer дали 0 target calls и timeout; это не успешная проверка игры.
Оба созданных для этих попыток процесса игры закрыты; tracer отсоединился.

Также literal 0.805F и float(0.7F * 1.15F) отличаются на 1 ULP:
1062081659 против 1062081658. Это отдельный вопрос defaults/record mapping,
а не обнаруженная грубая подстройка мощности. Ни множитель 1.15 из Windows
исходника, ни коэффициенты реальных автомобилей не изменены.
Исходники, RVAs, ограничение scope и verifier: `motor-runtime-v40`.
