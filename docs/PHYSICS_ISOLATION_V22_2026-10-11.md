# Поэтапная проверка физики Windows → Mac

В обоих нативных пробниках добавлено независимое отключение сопротивления
движению кузова, лучевых контактов колёс и обоих коэффициентов трения кузова.
Пружины, демпферы, tire stiffness, мотор, тормоз, руление, игровая дополнительная
гравитация и коррекция ориентации также выключены в начальном сценарии.
ИИ и GameCar gameplay не вызываются. Геометрия колёс и масса сохраняются:
перемещение колёс для отключения контакта изменило бы инерцию PhysX.

Начальные переключатели сохраняют прежние игровые значения по умолчанию.
Контрольная матрица из 608 сценариев / 255864 отсчётов точно совпала с Mac v14
в каждом из двух профилей. Прошли 53 CTest и игровой physics smoke.

## Результаты

Каждый сценарий содержит 120 шагов по 1/60 секунды. Сделано два нативных
повтора на Windows в Parallels и два на Mac. Полное состояние и команды
повторяемы внутри каждой платформы. Windows остаётся эталоном.

| Этап | Сценарии | Отсчёты одного прогона | Максимальная ошибка координат | Максимальная ошибка скорости | Статус |
|---|---:|---:|---:|---:|---|
| 00: свободное движение | 9 | 1080 | 0 | 0 | Пройден |
| 01: только заданное ускорение | 108 | 12960 | 0 | 0 | Пройден |
| 02: гравитация и сочетание с ускорением | 48 | 5760 | 0 | 0 | Пройден |
| 03: контакт кузова с землёй | 24 | 2880 | 0.0000151182 | 0.0000146628 | Остались 12 сценариев с землёй |

В этапах 00–02 точно совпадают все наблюдаемые величины основного comparator,
включая ориентацию, угловой момент и скорость колёс. «Точно» здесь означает
равенство записанных чисел с девятью значащими цифрами. Это не доказательство
равенства при любых начальных условиях.

Ускорение проверяется по трём осям, при массах 300/1200/2400 и значениях
±0.2, ±3, ±10 единиц мира/с², с нулевой и ненулевой начальной скоростью.
Это внешнее ускорение, приложенное к кузову. Разгон от двигателя через
передачу, колёса и сцепление ещё требует следующих этапов.

## Что выявил контактный этап

Нулевое `bodyFriction` оставляло вторичный коэффициент трения в Windows.
Новый переключатель включает `NX_MF_DISABLE_FRICTION` и обнуляет все четыре
static/dynamic коэффициента в contact callback; на Mac обнуляются оба
коэффициента contact settings. В окончательном Windows-прогоне проверены
41280 записей с нулевыми коэффициентами. Колёса не имеют контактов и сил.

Затем проявилась разная семантика блокировки вращения: исключение вращательных
DOF на Mac меняет эффективную массу контакта. Для изолированного стенда выбран
уже существующий профиль `windows-source-v14.cfg` с `physx_frozen_pose=1`:
инерция сохраняется, ориентация восстанавливается после шага, как у PhysX.
Это уменьшило максимальную ошибку скорости с 0.0461797 до 0.0000146628.
Обычный игровой профиль этой проверкой не заменяется.

Остаток воспроизводим. Windows contact callback и SDK восстанавливают frame
через quaternion и дают очень малую горизонтальную компоненту нормали;
Mac использует строго вертикальную нормаль. Также остаётся небольшая разница
вертикальной скорости после удара. PhysX сообщает ненулевой остаток
`sumFrictionForce` (максимальный модуль 0.0771783), несмотря на выключающий
material flag и нулевые коэффициенты. Эта диагностическая величина сохранена,
её нельзя выдавать за точно нулевое измерение силы или скрывать допуском.

12 контрольных сценариев с той же высотой и блокировкой вращения, но без земли,
совпали точно. Устранение оставшихся контактных расхождений продолжается.

## Порядок дальнейшей работы

После контакта: пружины → демпферы → сцепление шин и боковое скольжение →
мотор/торможение/руление → трение кузова и угловые реакции → сочетания эффектов.
Для каждого эффекта нужны отдельные сценарии и проверки взаимодействия с
уже включёнными эффектами. После каждого исправления повторяются пройденные
этапы и полная матрица. Затем — настоящие трассы без ИИ, и отдельно гонки с ИИ.
Следующий эффект не считается проверенным, пока текущий этап не пройден.

## Повторение

Собрать Windows `experimental/build-spring-probe.cmd` с оригинальным PhysX SDK;
запустить с установленными PhysX/VC90 DLL из v14. На Mac использовать v21
экспериментальный SDK/адаптер плюс `isolation-v22-active-adapter.patch` и новые
заголовки/fixture из этого коммита. Предварительные SHA-256 адаптера указаны
в `experimental/isolation-v22-audit.json`. Патч предназначен для v21 активного
адаптера; канонический игровой адаптер сохраняет v14 с новыми переключателями.
Готовые пробники и полные исходные файлы активного прототипа приложены к релизу.

На каждой платформе с Python 3:

```sh
python tools/calibration/experimental/run_isolation.py \
  --platform windows --probe SpringProbe.exe --out windows-isolation

python tools/calibration/experimental/run_isolation.py \
  --platform mac --probe rrr3d_physics_spring_probe \
  --reference-dir windows-isolation --out mac-isolation
```

Нужна новая выходная папка для каждого запуска. Mac runner проверяет выключенные
эффекты, одинаковые настройки/команды, полноту и повторяемость измерений.
Код возврата 1 означает сохранённые физические расхождения и остановку лестницы;
код 2 означает нарушение контракта измерений. Проверка не ослабляет comparator.
`verify_isolation.py` позволяет повторно проверить четыре сохранённых файла.

Подробные результаты и хеши находятся в
`tools/calibration/experimental/isolation-v22-audit.json`. Общая цель совпадения
физики остаётся активной; эта работа не устранила все известные расхождения.
