# Подвеска: независимая жёсткость и коррекция положения, v16

Цель устранения всех расхождений остаётся активной. v16 — проверенный исследовательский этап; установленная рабочая сборка остаётся v14. Экспериментальная геометрия v15 и новая подвеска ещё не включены по умолчанию.

## Выявленная причина

Коэффициент 0,7 в прежнем адаптере уменьшал физическую жёсткость пружины. Изолированные измерения PhysX 2.8.4 показывают, что неявная реакция на скорость использует полную исходную жёсткость. Коэффициент нужен отдельно для смещения, которое исправляет пружина. Эксперимент добавляет `WheelSettings::mSuspensionSpringBiasFactor`, сохраняя исходные stiffness/damping.

Новый Windows-пробник проверил 36 комбинаций пружины, демпфера, массы, центра масс, начальной скорости и трения шин. По 12 кадров на случай; повтор при четырёх итерациях дал идентичные 432 физических samples. Дополнительные прогоны с 1, 2 и 8 итерациями отделяют ошибку конечного решателя от параметров пружины. Все варианты сохранены в независимом эталоне `reference-spring-first-v16.json`.

Первые координаты кузова совпадают с Windows в 32 из 36 проб при точности печати эталона; максимальное отличие в остальных четырёх — менее 8×10⁻⁹. скорость после завершающего прохода ещё отличается. Например, при жёсткой пружине Windows получает 0,150602505 при четырёх итерациях и 0,153005213 при восьми, Mac — 0,153022021. Координата первого шага в обоих случаях четырёх итераций — 10,7525501. Подгонка жёсткости ради окончательной скорости испортила бы совпадающее перемещение.

## Полная матрица

Каждый из четырёх прогонов содержит 608 случаев и 255864 samples. Это одна и та же исправленная Windows-матрица v14, включая действительную массу, инерцию и центр масс второго участника парного контакта. Новые короткие пробы не заменяют полную матрицу.

Взвешенная RMS для default-профиля:

| Параметр | Рабочая v14 | Только новая подвеска | Подвеска + геометрия v15 |
|---|---:|---:|---:|
| Положение | 0,26186779 | 0,25804821 | 0,24731296 |
| Скорость | 0,14747069 | 0,13122700 | 0,12905922 |
| Угол поворота | 0,11647447 | 0,11642607 | 0,09035829 |
| Длина подвески | 0,00572114 | 0,00415784 | 0,00407968 |

Падение тяжёлой машины с новой геометрией: RMS положения 0,352795 → 0,003216. До контакта кузова ошибка вертикальной скорости MonsterTruckBoss на соответствующем шаге уменьшается с 0,3834 до примерно 0,0001.

Регрессии сохранены в `spring-audit-v16.json` по каждому параметру и сценарию. DirtDevil ухудшается при несимметричном упоре передних и задних колёс. Раннее включение упора уменьшило ошибку его положения 0,004087 → 0,000251, но ухудшило мягкую подвеску. Отдельная поправка скорости помогла некоторым падениям, но ухудшила другие случаи; вариант с раздельной коррекцией скорости оказался особенно плохим у заднего борта. Все три эксперимента ограничителя отклонены и удалены из текущего прототипа. Задний борт с геометрией v15 также остаётся отдельной существенной регрессией.

## Проверки и воспроизведение

- Полная пересборка приложения и всех тестов; 47 CTest и 19 тестов сравнения проходят. В число CTest входит экспериментальная проверка бинарного сохранения нового поля и соседних настроек колеса.
- `source_spring_reference` проверяет 12 независимых реакций на изменение начальной скорости. Неверная жёсткость ×0,7 отвергается во всех 12 отрицательных контролях; первые результаты всех 36 тестов независимы от включения трения шин.
- Два полных контроля с отключёнными экспериментами: все 608 случаев и 255864 samples каждого профиля физически идентичны v14; совпадают также действительные параметры кузовов. Пробник повторил 36 случаев после полной пересборки.
- Игровые прогоны с новой подвеской: physics smoke и трассы 0/16/48 по 600 кадров прошли на обоих профилях. Трасса 64 проходит с frozen-профилем, но в первом default-прогоне не выполняет критерий прогресса AI. Повтор с новой подвеской и контроль с прежней подвеской прошли. Первый сбой не воспроизведён устойчиво; все результаты сохранены, равенство и повторяемость AI этим не доказаны.
- Parallels Windows 11 отвечает через `prlctl exec`; `caffeinate -dims` продолжает работать.

Патч `tools/calibration/experimental/spring-bias-v16.patch` применяется отдельно: пути `Jolt/` — внутри populated Jolt SDK после рабочих v14-патчей, путь `src/` — в проекте. Он проверен применением к производственной базе, контрольные SHA записаны в `spring-bias-v16-base.json`. Для активации установить `RRR3D_EXPERIMENT_SPRING_BIAS=1`; для отключения убрать переменную целиком. Присутствие переменной, включая значение 0, активирует этот исследовательский прототип. Путь mesh включается отдельно через `RRR3D_EXPERIMENT_MESH_CONTACTS=1`.

После изменения SDK необходимо пересобрать всех его потребителей. Новое бинарное сохранение `WheelSettings` содержит дополнительный float; совместимость старых Jolt binary snapshots не заявляется. Оригинальные MotorRock assets используют исходный формат игры.

Mac-пробник: CMake target `rrr3d_physics_spring_probe`, выбор `list:spring-probe-0-0-0,...`. Эти 36 случаев доступны только при `MOTORROCK_EXPERIMENT_SPRING_PROBES`; обычная матрица сохраняет 608 случаев. Опциональный ABI-тест включается `RRR3D_BUILD_EXPERIMENTAL_SPRING_ABI_TEST=ON` только после применения SDK-патча.

Windows: `experimental/build-spring-probe.cmd SDK_PROG_PATH OUTPUT_DIRECTORY` собирает отдельный `SpringProbe.exe` через VC2008, используя установленный эталонный `C:\MotorRock\calibration\ReferenceEuler.obj`. DLL PhysX и Microsoft.VC90.CRT копируются из установленного эталонного стенда. Переменная `NX_SPRING_ITERATIONS` меняет число проходов только в этом отдельном пробнике; без неё остаётся 4. Рабочий Windows exe и исходный `windows.cpp` не изменены.

Следующее исправление должно воспроизвести завершение решателя и упор подвески совместно с контактами кузова. Снижение средней ошибки и прохождение служебных тестов пока не означают равенство Windows и Mac.
