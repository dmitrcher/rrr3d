# Порядок и завершение решателя подвески, v17

Цель полного совпадения с Windows/PhysX 2.8.4 остаётся активной: все четыре полные проверки сохраняют 572 случая с расхождениями из 608. Установленная рабочая сборка остаётся v14; патч v17 доступен отдельно для исследования. Эталонный Windows exe не изменён: SHA256 `e6eb63497a6a0425275cb71e0cc6e12f03e21bd8aa04ecf60baf40c0776502d2`.

## Проверенная модель

К 36 пробам v16 добавлены 27 скалярных случаев: 1/2/4 активных колеса под центром масс, три сочетания stiffness/damping и три начальные вертикальные скорости. Каждый случай независимо измерен в исходном SDK PhysX 2.8.4 при 1/2/4/8 итерациях в Parallels. Неактивные колёса расположены выше земли; их вклад в фактическую инерцию кузова сохранён в эталоне, а не исключён вручную.

При `dt`, исходных `k,d`, геометрическом смещении `C` и реакции строки `R`:

- `gamma = 1 / (dt * (d + dt*k))`;
- `effectiveMass = 1 / (R + gamma)`;
- `retention = R * effectiveMass`;
- начальный геометрический bias: `0.7 * dt * k * gamma * C`;
- после N обычных проходов заключительный проход использует `bias * (1 - retention^N)`.

Подвеска обходится в обратном порядке колёс в обычных и заключительном проходах. Изолированный математический тест воспроизводит 252 измерения: максимальная ошибка вертикальной скорости `2.745e-7`; компоненты момента отличаются менее чем на `0.00132`. Отрицательные контроли отвергают прежний конечный bias в 119 проверках и прямой порядок колёс в 80. Это вывод из измерений версии 2.8.4; открытый исходник более позднего [PhysX 3.4](https://github.com/NVIDIAGameWorks/PhysX-3.4/blob/master/PhysX_3.4/Source/LowLevelDynamics/src/DySolverConstraint1D.h) помог проверить форму мягкой строки, но не служит заменой эталону.

В самом Mac-адаптере максимальные ошибки первых шагов всех 252 проб: положение около `1e-6`, скорость `2.503e-6`. Эталон содержит также угловой момент и вращение; отчёт сохраняет все ошибки. Двенадцать шагов исходных 36 проб показывают оставшиеся расхождения: при четырёх итерациях до `0.01925` по положению и `0.30296` по скорости. Особый случай — прекращение контакта с землёй: у Windows ещё один шаг действует дополнительная реакция подвески. Гипотеза — сохранение строки предыдущего шага; это пока не подтверждено для всех условий. Подгонка границы луча не внедрялась; механизм ещё требует отдельной проверки.

## Совместное завершение подвески и контактов кузова

Дополнительный проход подвески выполняется вместе с заключительным проходом исходных контактов кузова; он не прибавляется отдельной поправкой после уже завершённого контактного решателя. Поза интегрируется с обычной скоростью, затем восстанавливается окончательная скорость.

Первый игровой прототип обнаружил assertion Jolt при восстановлении угловой скорости выше 7 rad/s. LLDB подтвердил место в `ContactConstraintManager::StoreAppliedImpulses`. Исправление временно допускает сохранённую скорость при установке и возвращает прежний лимит: следующее ограничение остаётся на следующем шаге, как в исходном адаптере Nx. Значение не обрезается, и ошибка не скрывается.

## Воспроизведение

Сначала применить рабочие SDK-патчи v14, затем исследовательские mesh v15 и spring-bias v16. `spring-final-v17.patch` применяется к этой базе: пути `Jolt/` относятся к SDK, `src/` — к проекту. Все восемь файлов патча воспроизведены из базы с совпадением SHA256 (`spring-final-v17-base.json`). После изменения SDK пересобрать всех потребителей.

Включение: `RRR3D_EXPERIMENT_SPRING_BIAS=1`, `RRR3D_EXPERIMENT_SPRING_FINAL=1`; геометрия отдельно через `RRR3D_EXPERIMENT_MESH_CONTACTS=0/1`. Для отключения убрать переменные. Параметр FINAL активируется только значением `1`, bias v16 — наличием переменной. `RRR3D_EXPERIMENT_SPRING_ITERATIONS=1/2/4/8` нужен только для изолированных проб; без него остаются четыре прохода.

Mac target `rrr3d_physics_spring_probe` включает дополнительные 63 случая только через `MOTORROCK_EXPERIMENT_SPRING_PROBES`. Обычный стенд сохраняет 608 случаев. Windows: `build-spring-probe.cmd SDK_PROG_PATH OUTPUT_DIRECTORY` и `NX_SPRING_ITERATIONS`; неизменённый эталон игры не пересобирается этим скриптом. Проверка модели: `python3 tools/calibration/experimental/test_spring_final.py tools/calibration/experimental/reference-spring-first-v17.json`.

Воспроизводимость численного стенда и служебные тесты не доказывают совпадение всей игры или AI. Исследовательский путь остаётся выключен по умолчанию до устранения воспроизводимых регрессий.

## Проверки и оставшаяся регрессия

После полной пересборки прошли 48 CTest и 19 проверок инструмента сравнения. Отключённый прототип повторно проверен до и после исправления угловой скорости: 608 случаев и 255864 samples на каждом из двух профилей физически идентичны v14, включая действительные параметры тел.

После исправления assertion physics smoke и трассы 0/16/48 по 600 кадров прошли на обоих профилях. Трасса 64 не прошла критерий прогресса/выживания AI на обоих профилях; ещё два default-повтора также не прошли. Контроль с отключённым прототипом прошёл. Это воспроизводимая игровая регрессия v17, поэтому установленная сборка не заменялась. Случай предыдущего v16, где один повтор проходил, не используется для оправдания нового результата.

Четыре полные численные матрицы снимались до исправления assertion; они завершились без assertion, а изменение setter сохраняет сами значения. После исправления все 1836 изолированных sample-ошибок остались идентичны, а полные отключённые контроли пересняты. Все сырые результаты сохранены локально; большие JSONL сжаты только с проверкой SHA256 после распаковки.
