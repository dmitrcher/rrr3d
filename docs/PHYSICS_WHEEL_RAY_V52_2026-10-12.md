# Восстановление геометрии лучей колёс: v52

Найдены две причины расхождения входов подвески. Windows строит луч от исходной точки колеса; Mac использовал поднятое на радиус начало. Кроме того, PhysX вычисляет точку попадания через вершины треугольника, а Mac получал её непосредственно на луче. На больших треугольниках разный порядок операций float32 меняет координаты контакта и плечо силы.

Внутренняя трассировка неизменённого оригинального Windows-пробника показала:

- Координаты уже различаются в результате поиска луча; публичный отчёт колеса их не изменяет.
- PhysX сначала строит мировой конец отрезка, затем снова вычитает начало. В первом контакте settle длина равна 0.8999996185302734, а не номинальному значению float32 0.9.
- Для весов `u`, `v`, `w = (1 − u) − v` исходный порядок сумм различается по координатам: X — `(A*w + C*v) + B*u`, Y — `(B*u + A*w) + C*v`, Z — `(A*w + B*u) + C*v`. Каждое действие округляется отдельно.

Независимая реализация C++ на arm64 побитно воспроизвела расстояние, оба веса и точку контакта для 24 реальных лучей из семи сценариев. Проверены settle, spring-soft, suspension-drop, две наклонные поверхности и штатные marauder/guseniza. Для каждого Windows-захвата выполнены два повтора и подтверждено сохранение всех 600 исходных состояний. Проверка с `-O0` и `-O2` дала одинаковые точные результаты.

Исправления включаются двумя независимыми экспериментальными флагами. Выполнены восемь прогонов, каждый с четырьмя сценариями: два контрольных, два с новым началом луча, два с новой точкой и два с обоими исправлениями. Результаты каждого варианта точно повторяются. Контрольный вариант сохраняет поведение v51.

| Проверка первого касания | settle, шаг 20 | spring-soft, шаг 38 | suspension-drop, шаг 38 |
|---|---|---|---|
| Все точки, нормали и длины четырёх подвесок | Точное совпадение | Точное совпадение | Точное совпадение |
| Положение после шага | Точное совпадение | Точное совпадение | Точное совпадение |
| Линейная скорость после шага | Точное совпадение | Точное совпадение | Осталось расхождение |
| Угловой момент и вращение | Осталось расхождение | Осталось расхождение | Осталось расхождение |

В settle вертикальная скорость стала точно равна Windows: −5.44084072. Ранее она составляла −5.44084024. Геометрическое исправление подтверждено отдельно от остающейся ошибки решателя.

Ограничения текущего эксперимента: исходное начало луча восстановлено только для единичного физического кватерниона машины; преобразование частного повёрнутого положения колеса ещё предстоит трассировать. Точка восстанавливается только для зарегистрированных статических мешей с единичным преобразованием тела; выбор треугольника остаётся за Jolt. Поэтому флаги по умолчанию выключены, и длинное движение машины не объявляется исправленным.

Все 291 ранее подтверждённых физических теста сохранили побитное совпадение с Windows при свежих двойных контрольных и кандидатных прогонах. Полная Debug-сборка успешно упакована и подписана; прошли 53 из 53 CTest-проверок. Интерактивная гонка этим этапом не сертифицирована. Широкая матрица кандидата v52 ещё не пересертифицирована: последний опубликованный результат v51 — 65 из 608 точных сценариев, 543 остаются открытыми.

Мощность двигателя, массы, параметры шин, жёсткость и демпфирование не менялись. Исходные описания создаваемых ограничений подвески Windows сняты отдельно. Следующий шаг — сравнить подготовку строк, вычисление импульса и порядок его приложения. Прежняя формула финального смещения пружины v17 проверялась с допусками; это не доказательство её побитного соответствия оригинальному внутреннему решателю и не основание немедленно её удалять.

Исходники, точный patch, измеренные входы, проверка C++ и отчёты: [wheel-ray-v52](../tools/calibration/experimental/wheel-ray-v52/README.md). Общая цель устранения всех расхождений остаётся активной.

Продолжение: [v53 — подготовка строки и два накопленных импульса](PHYSICS_SPRING_SPLIT_V53_2026-10-12.md). Полное состояние первого контакта в трёх сценариях теперь совпало; следующие шаги и полные заезды остаются открытыми.
