# V90 static-contact node recycling investigation

Native SAP adjacency nodes are freed when their last pair disappears and reused from a LIFO free list. At contact recreation, identical insertion order can therefore produce a different published pair order. The old Mac model retained empty nodes and omitted static mesh bounds. This default-off overlay models observed node recycling, adds source mesh bounds, and recreates spring/hard-stop construction IDs when static contact creation serials change. It changes no engine, grip, mass, suspension, damping or timing coefficients and takes no recorded Windows state as runtime input.

Two read-only Native captures preserve all 600 physical states each. The node helper reproduces 46 publications and 8 pre-insert allocation checkpoints at O0/O2. Disabling recycling fails the observed free-head check. Native inserts wheel pairs in the same order at steps 19 and 44; actual publication reverses at 44 after removal at 38. Run `python3 verify-native-nodes.py` to derive fixtures directly from included captures and compile the actual helper.

Current integration is deliberately limited to one TrackPlane collision mesh, one vehicle, and no decorations. Other scenes retain the previous ordering path. Arbitrary mixed creation/removal cancellation and multi-actor/multi-mesh behavior are not certified. There is no frame, fixture-name, or prescribed permutation branch.

Full 608-case comparison, two fresh repeats of 255864 states: **242 strict matches / 366 open; zero previously exact cases lost; zero new completely exact cases.** High-load isolated trajectories now match every observable through step 57; the first difference moves from 44 to 58. Of 608 complete histories, 561 are unchanged and 47 change. Error maxima also worsen in some open cases: position 7, velocity 14, orientation 5, angular velocity 8, suspension 8, normal force 14. Contact mismatch counts are unchanged. Full reports retain those regressions. This is a reproducible investigation checkpoint, not universal improvement or full race parity.

All 291 independent gates pass fresh control/candidate runs twice. Full game build, 53 CTests, solo real-track functional launch and rendered AI functional launch pass. The ordinary installed game remains at its previous baseline; the included numerical probes use an explicitly enabled research profile. AI launches are functional smoke checks, not parity tests.

This four-file overlay requires the exact V88 source base, available in the [verified V88 research release](https://github.com/dmitrcher/rrr3d/releases/tag/physics-v88-242-exact-investigation-2026-10-13). `apply-experiment.py --adapter-root PATH --sdk-root PATH` validates every file before mutation and supports idempotent installation or `--restore`. Rebuild afterward. `candidate-environment.json` enables `RRR3D_EXPERIMENT_NATIVE_STATIC_CONTACT_NODES_V90` and its prerequisites; all source switches default off.

Run `python3 verify-checkpoint.py --probe PATH` to reproduce 1200 fresh states against the retained Mac repeats and immutable Windows subset. The frozen manifest describes its capture-time status; separate probe validation records completed acceptance checks.
