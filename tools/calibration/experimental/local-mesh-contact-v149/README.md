# Local mesh contacts V149 — experimental runtime correction

The V143 experimental adapter clips placed meshes in world coordinates and independently selects triangle planes. V149 adds a default-off path (`RRR3D_EXPERIMENT_NATIVE_LOCAL_CONTACT_V149=1`) that builds flat-part topology from geometry, computes relative poses through the original quaternion arithmetic, clips in mesh-local space and returns the contacts to world coordinates. Material/cache code retains its world-space box transform. No engine, friction or suspension coefficient is adjusted.

The part builder follows the original Cooking tests: adjacent faces split into flat parts when the absolute atan2 angle exceeds float32 0.01, read at VA100515b4; a positive opposite-vertex plane distance additionally cuts convex parts. The original strings and caller at RVA16090 establish the meanings of the two tables. On the complete 32-triangle border mesh, all convex/flat equivalence relationships match the original (9 convex parts, 18 flat parts) at O0/O2, in both original Source and cooked triangle orderings (8192 predicates). Numeric component labels are not claimed to match native labels. General cleanup/welding, edge activation and threshold-boundary precision remain open.

`contact-selection-v148` contains the read-only original observer and actual key tables. The final `native-keys` capture is authoritative; the earlier observer revision lacks those fields. Both map0 sample342 and map16 sample244 preserve two complete original 900-state histories and executable/SDK/fixture hashes.

The V149 runtime now matches all four world-space contact positions and raw separations at map0 physical342, and the first two solver rows match effective mass, bias and lever arms exactly. Four-map 900-step runs remain repeat-identical (map0 was also rechecked after removal of unused metadata prediction), with first differences still342/244/358/238; this is not full moving parity. At the first collision, velocity L2 error falls from 0.00118358 to 0.0000433239 and angular momentum error from 1.06776 to 0.0410411. These are local error measurements, not a whole-race improvement claim.

The next cause is isolated: original rows0/1 and rows2/3 use different per-triangle callback material frames. The current Jolt adapter applies one frame to all points. Computing the frames independently with each triangle's public normal reproduces all eight original solver-quaternion words exactly (`live342-proof.json`). Per-contact frame propagation through the Jolt manifold/settings/constraint data is the next required implementation.

The local path still lacks original convex-part global SAT/representative-face selection for multiple flat parts and uses the old active-edge flags. Do not promote it as a complete cooking or collision implementation. Default-off map0 retains all900 V143 states. All53 CTest tests pass. The first complete608-case regression matches the original in all255864 physical states. The second repetition is still running; two-repeat validation remains pending.

The guarded four-file installer accepts the verified V143 research adapter only. It must not be applied to the ordinary older production root. No SDK code or ABI is changed by V149. No ordinary installed game is promoted by this experiment.
